# 008. 좌석 배치도 렌더링 방식 + 키보드 내비게이션

## 상황

좌석 배치도를 화면에 그릴 방법과 키보드 사용자 대응 방식을 결정해야 했다.
렌더링 기술 선택이 접근성 구현 비용을 결정하기 때문에 두 판단을 함께 다뤘다.

## 렌더링 방식 결정 — DOM (button + CSS Grid)

### 검토한 선택지

- **DOM**: HTML 요소. 포커스, 키보드, 스크린리더 대응이 기본 제공. CSS와 잘 맞음.
- **SVG**: 좌표 기반. 접근성은 DOM과 비슷하나 CSS Modules 적용에 제약.
- **Canvas**: 고성능. DOM 노드 없어서 접근성 전부 직접 구현 필요.

### 결정과 이유

**DOM + CSS Grid** 선택.

1. 1차는 200석이다. 측정 없이 Canvas를 고르는 건 조기 최적화다.
2. 좌석은 누르는 것이라 `button`을 써야 한다. Canvas는 포커스 대상이 없어 별도 레이어가 필요하다.
3. CSS Modules + `data-state` 결정(002)과 가장 잘 맞는다.
4. 2차에서 5,000석으로 늘려 측정한 뒤 이 결정을 재검토하는 것이 프로젝트 설계 의도다.

### 세부 구현 결정

- 좌석 요소: `<button>` (div가 아님 — 포커스, Enter/Space, 역할 안내 기본 제공)
- 판매 완료 좌석: `disabled` 대신 `aria-disabled="true"` — 포커스는 되게 하여 스크린리더 사용자가 좌석 존재를 알 수 있게 함
- 배치: CSS Grid. `gridRow`/`gridColumn`을 인라인 style로 전달 (위치 데이터이지 스타일 결정이 아님)
- 스타일: CSS Modules + `data-state` 속성으로 상태별 스타일 분기

## 키보드 내비게이션 결정 — Roving tabindex

### 검토한 선택지

- **모든 좌석을 탭 순서에**: 200번 탭을 눌러야 원하는 좌석에 도달. 스크린리더 사용자에게 비현실적.
- **Roving tabindex**: 그리드에 탭 하나로 진입, 화살표키로 이동. 표준 ARIA grid 패턴.

### 세부 결정

- **처음 진입 시**: 1행 1열 첫 번째 좌석. 세션 간 기억 안 함 (좌석 상태는 계속 바뀌므로 이전 포커스가 유효하지 않을 수 있음). 같은 화면에 있는 동안의 마지막 포커스 좌석은 컴포넌트 상태로 기억.
- **행 끝에서 오른쪽 방향키**: 멈춤. 좌석은 물리적 공간이라 A열 끝에서 오른쪽으로 가면 벽이다. 공간 은유를 깨면 스크린리더 사용자가 방향 감각을 잃는다.
- **열 끝에서 아래 방향키**: 멈춤. 같은 이유.
- **판매 완료 좌석**: 건너뛰지 않고 포커스 허용. 어디가 팔렸는지는 좌석 선택에 필요한 정보다. 건너뛰면 스크린리더 사용자는 그 좌석의 존재를 알 수 없다. `aria-disabled="true"` 결정과 일관됨.
- **Home/End**: 지원. 현재 행의 처음/끝으로 이동. 한 행에 20~30석이면 유용하고 구현 비용이 낮다.
- **PageUp/PageDown**: 미구현. 200석은 한 화면에 다 보이므로 의미 없다.
- **Ctrl+Home/End (전체 첫/마지막)**: 미구현 (1차 범위 밖).

### 키 이벤트 처리 방식

- **화살표키**: `onKeyDown`에서 `preventDefault()` (페이지 스크롤 방지) + 다음 좌석으로 `.focus()` 이동
- **Space**: `onKeyDown`에서 `preventDefault()` (페이지 스크롤 방지). 선택 동작은 `onClick`으로 처리 (button 기본 동작)
- **Enter**: 별도 처리 불필요. button 기본 동작으로 `click` 이벤트 발생
- **화살표키는 이동만, 선택은 Enter/Space** — 이 구분이 명시적으로 유지됨

### 불규칙 격자 처리 — 가장 가까운 열, 동거리 시 낮은 열 번호

화살표키로 이동했을 때 해당 행/열에 대응되는 좌석이 없는 경우:

- **가장 가까운 열**로 이동. 예: 1행 2열에서 ArrowDown, 2행에 2열이 없고 1열·3열만 있으면 둘 다 거리 1.
- **동거리 타이브레이커**: 낮은 열 번호. 위 예에서 1열로 이동.
- 이동할 수 있는 좌석이 없으면 (`null` 반환): 멈춤.

**이유**: 공간 은유 유지 + 결정론적 동작. 낮은 번호 우선은 임의적이지만 일관성이 예측 불가능보다 낫다. `reduce`에서 `<` (동거리 무시)로 구현되어 타이브레이커가 코드에 명시됨.

**Position 타입**: `{ row: number; col: number }` — 둘 다 1부터 시작, SeatBase와 동일 단위. 배열 인덱스는 함수 내부에서만 `row - 1`, `col - 1`로 변환. 퍼블릭 타입에 0-based 이름(`rowIndex`, `colIndex`)을 노출하지 않는다.

### 스크린리더 레이블

```
aria-label="{행}열 {열}번, {상태}"
예: "A열 3번, 예매 가능" / "B열 7번, 판매 완료"
```

## 이 결정이 틀렸다면 어떻게 알 수 있나

좌석 수가 늘어나 첫 렌더나 상태 변경 시 눈에 보이는 지연이 생기면 재검토한다.
2차에서 5,000석으로 측정할 때 이 결정을 다시 판단한다.
비교할 기준선을 H단위에서 기록해둔다.

## 되돌리는 비용

DOM → SVG: SeatGrid 컴포넌트와 CSS를 교체. 타입과 상태 관리 로직은 유지 가능.
DOM → Canvas: 키보드/접근성 레이어 전면 재작성 필요. 비용 높음.
